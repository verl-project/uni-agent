# 用例提交指导书

## 一、用例基本原则

- 当前仅支持运行在CPU后端的UT用例。
- 统一提交到`tests/uni_agent`目录下，该目录之外的用例不会在门禁中运行。
- 在`tests/uni_agent`目录下，按照功能模块分别进行提交。

## 二、用例提交步骤

### 1、运行依赖统一放在根目录下的`requirements-test.txt`中

### 2、参考上节所述原则将用例提交到指定位置

### 3、给用例增加标签，用来指定运行的后端和用例的等级

#### 支持的标签：

- cpu: 指定用例运行在CPU后端上 
- gpu: 指定用例运行在GPU后端上（暂不会实际运行）
- npu: 指定用例运行在NPU后端上（暂不会实际运行）
- level0: 指定用例为门禁级别用例，每次运行门禁均会运行
- level1: 指定用例为版本级别用例，仅在版本验证时人工运行。

#### 注意事项：

- 按照函数粒度配置标签，请勿直接给类配置标签。
- 需要同时指定后端和用例等级标签，用例才会在门禁中运行
- level0, level1 在一个用例中仅可指定其中之一

#### 用例示例

脚本名格式：`test_xxx.py`

```

import pytest


@pytest.mark.cpu
@pytest.mark.level0
def test_xxxx():
    ...

```

### 4、提交用例所需数据集，权重到门禁机器中

当前不支持，待补充。

## 三、门禁用例验证方法

### 1、逻辑验证

在PR的 checks 选项卡中，找到 Python Backend CI 工作流，该工作流下有两个子工作流，点击查看对应的门禁日志。

日志中包含`用例运行信息`和`覆盖率统计结果`。

需要保证用例运行无报错才能合入。

### 2、覆盖率验证

**当前该验证仅为建议项目，未设置强校验**

Python Backend CI 工作流运行完成后，会在PR中新增覆盖率评论，显示该PR的修改所对应代码的覆盖率。

包括：`修改代码的覆盖率`和`按照代码行显示的覆盖情况`。

建议按照结果完善用例覆盖率。
